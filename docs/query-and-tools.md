# 查询、记录与话题上下文

更新：2026-10-14。本文描述当前代码，不把模拟模型测试视为真实模型验收。

## 设计分工

采用一个 agent 和四个工具。模型理解意图、选择工具、整理用户事实；程序验证参数、原文出处、宠物归属、日期、记录统计与保存确认。没有新增框架、向量库或多 agent。

正式日记只在用户点击「保存这条」后写入。模型没有直接保存、修改或删除日记的工具。模型失败会尝试 JSON 模式，两种模式都失败时显示错误与重试，不再生成本地演示回答。

## 工具

| 工具 | 主要参数 | 行为 |
|---|---|---|
| `query_records` | eventType、keyword、startDate、endDateExclusive、mode、limit、offset、purpose | 查询当前宠物已保存的日记；不指定事件即可列出全部 |
| `create_draft_record` | text、sourceText、date、tags | 摘取用户事实原文，整理一张待确认卡，不写正式日记 |
| `read_conversation` | offset、limit | 分页读取当前话题完整对话，包括未放入默认提示词的早期消息 |
| `read_session` | id、offset、limit | 按目录 id 分页读取历史话题，只读，不切换当前会话 |

近期回顾也由 `query_records` 完成，移除了与它重叠的 `list_recent_records`。

工具最多执行六轮，最后仍有工具调用时会再发起一次不带工具的收尾请求。这个上限用于限制单次请求耗时，不限制用户能聊多少轮。工具错误会返回模型，让它修正参数；已经修正的错误不会再冒充最终事实。

## 日记查询

数据入口是 `utils/query.ts` 的 `queryRecords(options)`。云模式下读取 repository 已同步到本机的日记缓存，因此不是实时的服务端检索。宠物 id 和参考日期由执行器注入，模型不能跨宠物查询。

```ts
interface RecordQueryOptions {
  petId: string;
  eventType?: EventType;
  keyword?: string;
  startDate?: string;        // YYYY-MM-DD，包含
  endDateExclusive?: string; // YYYY-MM-DD，不包含
  mode?: 'latest' | 'count' | 'list';
  limit?: number;            // 1..50，默认 3
  offset?: number;           // 非负整数，默认 0
  referenceDate?: string;
}
```

事件类型：bath、deworming、vaccination、vet_visit、feeding、cleaning、play、outing、elimination、sleep。

处理顺序：宠物隔离 → 事件/关键词及日期筛选 → 按发生日期倒序 → 统计全部匹配 → 分页返回。`latest` 每页一条；其他模式每页最多 limit 条。返回 summary、totalMatched、latestDate、daysElapsed、records、refs、nextOffset。没有下一页时 nextOffset 为 null。

`purpose` 是 agent 层的显示参数：

- `answer`（默认）：直接展示程序生成的事实摘要与引用，不采用模型另写的日期或数字。
- `context`：适合咨询、比较、回顾；展示事实摘要，同时保留模型结合工具结果生成的自然回复。推理与建议仍需真实模型评测。

模型可以依据上下文查询，例如「那疫苗呢？」无需命中本句查询关键词。一次查驱虫和疫苗时，两次工具调用保留各自的参数，程序不再用用户原话中的第一个事件覆盖所有调用。日期表达由模型转换为日期参数，再由程序校验真实日历日期与起止顺序。

`resolveQueryOptions` 保留为明确历史问题漏调工具时的有限补救，及 JSON 模式漏给 query 时的补救。它仍只支持常见事件、月份、周、最近 N 天和明确起止日期；正常模型查询不经过它。它不是通用的自然语言解析器。

查询本身仍是原文/标签匹配，不能宣称已有语义检索。药名不会自动推断成驱虫，宽泛「医疗」标签不会自动匹配驱虫。对于「最近有没有不舒服」等描述性问题，模型可以先按时间列出日记、分页阅读后再判断。未读完不能声称检查过全部；这类推理结果不能直接冒充工具的精确事件统计。

`totalMatched` 统计日记条数，一条日记可能包含多次事件。旧日记的否定、计划等过滤仍是有限规则，可能漏掉特殊表达；有歧义时应回看原记录。

## 记录依据与日期

模型负责判断事实、计划、否定、咨询及混合句。移除了草稿校验中用否定词和双字重叠判断语义的拦截，避免「没想到今天驱虫这么顺利，没有不良反应」被拒绝。

工具必须提供 sourceText，从当前话题的用户原话逐字摘取事实分句。程序验证该分句确实出现在用户消息中，助手建议不能作为原文出处。只说「把刚才的记下来」时，可引用前文用户明确陈述的事实；没有事实或指向不明时由模型追问。

正文使用模型整理的版本；rawInput 保留包含证据分句的整条用户消息。直接输入保留未 trim 的原文，跨轮记录不会把「记一下」这个指令当成事实原文。

sourceText 的逐字引用要求不约束正文 text：正文可以整理语法、去除赘词，原话已经自然完整时也可保留。日期独立展示后，正文通常省略「今天/昨天」，保留具体时段，例如「昨晚和点点玩逗猫棒」可整理为「晚上和点点玩了逗猫棒」。不能为了润色补出未陈述的心情或时长。工具模式和 JSON 模式共用这份写作说明，标签要求使用简短中文。

日期不直接相信模型字段，而从选中的事实分句解析。相对日期使用原消息发送日期，重新打开旧话题后不会把旧消息的「昨天」解释成今天的昨天。分句中出现多个不同日期、模糊日期或解析不了时留空，由用户点选。不能据此宣称代码已经证明所有模型整理内容都与原文语义一致。

同次请求最多一张草稿。不同日期的多个事件建议分开记录；当前没有实现批量多卡整理。

## 上下文与会话

默认提示词按 12000 字符预算选取最近消息，不按八轮截断。较早消息仍在当前话题中，模型可通过 read_conversation 分页取回。查询回复进入下一轮上下文；失败通知和单纯流程提示不作为事实上下文。

历史话题通过标题目录按需读取，取回内容只供模型参考，不将整段历史原文自动拼到用户回复中。话题目录当前最多提供最近十个其他话题。

会话文档仍有 100 条消息的存储上限；发送前会为本轮预留三条消息，接近上限自动开启新话题并保留旧话题。超过存储上限的同步会明确报错，不再静默裁掉最早消息。这是存储边界，不是模型只能记住 100 条；开新话题、30 分钟间隔自动开新话题都仍是显式上下文边界。

30 分钟超时现在提前处理：打开聊天页、切换宠物或恢复页面时立即检查，页面停留期间使用一个定时器在到期时开启新话题并显示分隔提示，不再等用户发送才切换。分隔条不进入模型上下文，也不会因重复进入页面而重复创建。新话题开始时保留输入框中未发送的文字和附件，旧话题可从目录查看。主动从目录打开旧话题允许继续聊，此时从打开时重新计时；生成回复、处理照片、保存或编辑记录、读取旧话题期间暂停自动切换，完成后重新检查。

同步按顺序提交，复用上次返回的 id/版本。回包只更新云端身份和版本，保留本机尚未入库的照片、重试信息和原文。旧请求不能覆盖新话题；读取旧话题不写当前槽位；云端草稿恢复当前宠物 id。编辑草稿照片后重新对齐 fileId，避免保存已删除的旧图。

照片只在保存日记时上云，因此尚未保存的本机照片不会在另一台设备出现。仍没有实现复杂的跨设备冲突合并；冲突时保留本机内容并提示重新打开话题。

## JSON 降级

要求完整 reply、draft、query 对象，不接受普通文字伪装成功。draft 可带 sourceText，query 可带 offset；沿用相同的草稿与查询校验。旧兼容输出未给 sourceText 时，只能以当前用户输入作为依据，不能通过这种省略方式引用前文。

JSON 模式没有按需读取历史话题或长对话的工具，不能假装与完整工具模式能力一致。它返回 query 时以该参数执行；返回的自由文字不能覆盖确定性查询摘要。

## 测试与真实模型验收

默认自动化：

```sh
cd tools
npm run typecheck
npm test -- --runInBand
```

真实模型评测单独运行，不进入默认测试或 CI，使用合成日记，不读个人日记，也不会保存正式记录。共十四个场景：事实记录、日记正文整理与中文标签、否定、计划、咨询、否定词误伤、混合日期、跨轮记录、缺事实追问、助手建议隔离、多事件查询、省略追问、日记回顾、长对话取回。

PowerShell 中设置自己的兼容服务配置后执行：

```powershell
$env:DIARY_EVAL_BASE_URL = 'https://你的兼容服务地址/v1'
$env:DIARY_EVAL_MODEL = '你的模型名称'
# DIARY_EVAL_API_KEY 从自己的安全环境注入，不要写进仓库。
npm run eval:agent
```

该命令会发起真实网络请求并计费，只记录场景名、耗时、工具名称、卡片和引用数量。更换模型或修改提示词后可重复运行；一次通过不代表所有真实输入都可靠。

微信开发者工具与真机还需验证：图片编辑保存、生成中切换宠物/话题、照片跨设备展示、云端权限和真实模型兼容性。Node 测试不替代这些验收。

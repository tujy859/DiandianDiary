# 查询、工具与降级说明

更新：2026-10-12。本文描述已经实现的行为。

## 数据和统一查询入口

当前数据仍保存在微信本机 Storage，没有云端查询接口、向量库或 RAG。`utils/query.ts` 导出的 `queryRecords(options)` 是统一的本地接口，工具调用、JSON 降级和本地演示共用它；以后可以保持契约不变，再替换成云开发查询。

```ts
interface RecordQueryOptions {
  petId: string; // 执行器注入当前宠物，模型不能跨宠物查询
  eventType?: EventType;
  keyword?: string;
  startDate?: string;        // YYYY-MM-DD，包含
  endDateExclusive?: string; // YYYY-MM-DD，不包含
  mode?: 'latest' | 'count' | 'list';
  limit?: number;            // 1..50，默认 3
  referenceDate?: string;    // 请求参考日期，默认本地今天
}
```

事件类型：`bath`、`deworming`、`vaccination`、`vet_visit`、`feeding`、`cleaning`、`play`、`outing`、`elimination`、`sleep`。

处理顺序是宠物隔离 → 具体事件/关键词 → 日期范围 → 倒序排列 → 统计全部匹配 → 截取展示条数。`latest` 只返回一条；`count` 和 `list` 的展示最多 `limit` 条。`limit` 不影响 `totalMatched`。

返回 `summary`、`totalMatched`、`latestDate`、`daysElapsed`、`records`、`refs`。摘要、日期、距今天数和引用都由代码生成。统计的是已保存的日记条数，一条日记可能描述多次事件，不能等同于真实发生次数。

展示标签仍可使用「医疗」，但检索驱虫只匹配原文中的驱虫或明确的驱虫标签；不会把疫苗或只有「医疗」标签的记录算成驱虫。旧数据直接兼容读取，不自动修改原记录。药名本身不推断用途；仅记录药名但未说明驱虫的旧日记可能需要用户补充信息。

## 日期范围

`resolveQueryOptions(text, args, referenceDate)` 将原话与模型参数转换为查询选项。能确定的原话事件、范围和计数意图优先，避免模型把驱虫理解成疫苗或漏掉「这个月」。罐头、刷牙等细分项目保留关键词，不扩大成所有喂食或清洁。

已支持：

- 这个月/本月、上个月；本周/这周、上周（周一开始）。
- 最近 N 天：包含今天，`最近7天` 是今天及之前六天。
- 今天、昨天；`2026年10月`、`10月`（年份没有歧义时）。
- `2026-10-01 至 2026-10-12`、`10月1日到10月12日`，人类输入的结束日包含在内。
- 带年份的跨年日期范围。

例如参考日为 2026-10-12：

```ts
queryRecords({
  petId: currentPet.id,
  eventType: 'deworming',
  startDate: '2026-10-01',
  endDateExclusive: '2026-11-01',
  mode: 'count',
});
```

「上周左右」、未实现的相对范围、无年份的跨年范围会要求明确日期，不会静默查询全部。日期必须是真实日历日期，起止顺序必须正确，条数必须为有界整数。旧库里的非法日期不参与查询；新增/修改记录也会校验日期。

「今天该不该洗澡」中的今天属于决策时间，不会把参考的历史洗澡记录限制为今天。混合消息中的事实时间也不会错误限制后面的历史查询。

## 三个模型工具

| 工具 | 参数 | 行为 |
|---|---|---|
| `query_records` | eventType、keyword、startDate、endDateExclusive、mode、limit | 执行统一查询，返回事实和原记录引用 |
| `list_recent_records` | startDate、endDateExclusive、limit（默认 5） | 列出当前宠物近期日记，按发生日期倒序 |
| `create_draft_record` | text、date、tags | 校验用户事实后生成一张待确认草稿，不写正式记录 |

这些是模型协议里的函数定义，不是 HTTP 接口。`utils/agent.ts` 的 `TOOLS` 对模型公开 schema，`runAgent` 最多发起三轮模型请求。本地再次校验参数，不依赖模型遵守 schema。

明确的历史查询直接展示本地查询摘要，不采用模型重新生成的数字和日期；模型漏调工具时也会执行本地事实查询。咨询场景保留模型建议，同时展示检索到的事实和引用；建议内容仍是模型输出，不能视作已经验证的专家知识库。

`utils/draft.ts` 的 `validateDraft` 同时供工具和 JSON 使用：咨询、计划、否定、纯闲聊不能出记录卡；混合消息只保留事实分句；草稿正文使用用户原话，避免模型改写药名或数字；日期不明确就留空，交给用户确认。重复调用工具只产生一张草稿。

只说月日或几号时，不会把尚未到来的日期静默猜成去年或上个月。旧数据中非法日期显示「日期待修正」，仍能进入编辑修复。

正式入库只发生在用户点击「保存这条」后。已保存卡片不能重复新增；修改正式记录仍通过日记详情完成。模型没有修改/删除正式记录的工具。

## JSON 降级

流程：工具调用 → JSON 模式 → 明确标识的本地演示。

JSON 模式有独立的提示词，并发送 `response_format: { type: 'json_object' }`，要求完整结构：

```json
{
  "reply": "先整理为草稿，确认后再保存。",
  "draft": { "date": "2026-10-12", "text": "今天给咪咪洗澡了", "tags": ["洗澡"] },
  "query": null
}
```

历史查询用 `query` 对象，字段与查询工具相同；不需要的 `draft`/`query` 必须为 null。以前的 `queryTag` 已替换成支持范围的 `query`。

解析器校验完整 JSON 和字段类型、日期、查询参数；完整 JSON 代码块可以解析，自由文字、缺失字段、夹带说明或非法结构会失败。失败会进入本地演示，显示原因和重试入口，不再把普通文本伪装成结构化成功。

某些兼容服务不支持 tools 或 `response_format`；如果两者都失败，本次明确降为本地演示。JSON 模式仍需用户确认，不降低事实校验或保存门槛。

## 请求隔离与重试

每次请求拥有独立的 `RequestToken`，工具轮次和 JSON 降级共用这个信号。

- 停止会立即取消等待并调用微信 `RequestTask.abort()`；迟到结果不追加消息。
- 切换宠物或离开页面取消当前生成；旧请求不能写入新宠物的聊天。
- 旧请求的 finally 只能清理自己的状态，不能覆盖新请求。
- 照片处理期间锁定发送；切换宠物后，旧照片处理结果不会产生新消息。
- 重试保留原请求照片，历史中不重复本轮用户消息；已有后续对话时不截断聊天去重试旧消息。

## 验证边界与下一步

自动化测试涵盖统一查询、日历边界、非法参数、模型误调工具、JSON 校验、取消请求及真实聊天页事件方法的异步竞争。这些是 Node 下的模拟测试，不等于微信开发者工具编译或真机验收。

建议真机复验：驱虫与疫苗交替记录、这个月统计、日期修改/删除后再次查询、停止后立即发新消息、生成中切换宠物、服务不支持 tools/JSON 时的降级和重试。

还没有云同步、语义检索或经过审核的养宠知识库。自然语言理解和旧日记的关键词匹配仍可能有歧义；明确的事件字段和云端存储可以作为下一轮演进，不能将当前规则宣称为所有语言场景的 100% 准确。

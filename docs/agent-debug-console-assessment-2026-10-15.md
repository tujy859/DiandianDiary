# 聊天回复与端侧调试台评估

日期：2026-10-15；依据 `8939a1e` 的源码和用户两张领养截图。本轮仅诊断与设计评估，没有修改正式聊天逻辑，也没有调用真实模型、读写私人日记或部署云函数。

后续已实现回复 / 引用修复、执行日志和端侧流程测试。本文保留评估时的诊断，当前使用方式与验证边界见[开发自检](developer-self-check.md)和[开发记录](development-log.md)。

## 已确认的程序路径

`utils/agent.ts` 在每次成功调用 `query_records` 后，将摘要加入 `factReplies / contextFacts`，将引用无条件加入共用 `refs`。最终正文优先展示 answer 查询摘要，但引用仍是所有查询的并集，只按 recordId 去重。因此内部宽泛查询的引用可能附在精确答案下。

使用当前源码、内存演示日记与模拟模型返回进行了两个复现，临时脚本位于被忽略的 `backups/agent-console-assessment-20261015/reproduce.cjs`：

| 场景 | 模拟工具序列 | 实际结果 |
| --- | --- | --- |
| 输入“25年10月1号领养了点点” | 领养关键词 context 查询 → 创建领养草稿 → 模型最终说明 | 没有找到领养的摘要 + 模型提及旧玩耍和待确认卡的说明 + 固定确认提示；草稿日期正确为 2025-10-01，未经确认不保存 |
| 新话题问“我什么时候领养的点点” | 领养关键词 latest / answer 查询 → 无筛选 context 查询 → 模型最终说明 | 正文只说 1 条领养记录，引用却包含领养、玩耍、驱虫三条；history 为空仍可复现 |

这是能产生截图同类结果的确定代码路径，不代表掌握了用户当时的真实工具轨迹。截图没有请求级日志，不能断言具体工具顺序或是否经过 JSON 降级。

第一张图还包含状态展示问题：保存只更新草稿卡的 saved 状态，不撤回或更新之前生成的“待确认”说明。记录尚未保存时查不到它本身合理，但背景查询不应主动成为这次记录操作的用户答复。混合回复以查询摘要开头，也绕过了 `buildHistory` 仅按开头过滤流程提示的规则，可能再次进入后续模型上下文。

领养目前可以通过 keyword 查询，并不是已定义的 eventType；不能把上述现象简单归因于记录中不存在领养，也不能靠增加工具循环轮数解决。优先应修正内部取证与可见答案的边界，并让可见正文和引用来自同一组结果；显式混合请求仍可同时显示相关查询与草稿。

## 端侧调试台的可行方案

可在现有开发自检入口扩展为三个区域，不另建测试服务或增加 agent 框架：

1. **核心自检**：保留目前 12 项离线、纯内存检查，自动运行仍只执行这些用例。
2. **流程测试**：用户主动开始后，使用独立测试家庭、每轮独立测试宠物与话题，走正式聊天、草稿校验、保存及查询链路。支持逐步执行；自动确认仅限用户启动的合成数据测试。复用已验证的测试家庭，避免每轮新建家庭消耗 10 个名额。失败停在现场，保留运行 ID 和已创建记录 ID；清理只能针对本轮创建的数据，不能清空当前家庭。
3. **执行日志**：按运行 / 步骤记录请求 ID、工具或 JSON 路径、降级原因、工具名及允许的参数、命中记录 ID / 日期、最终外显引用、草稿解析日期、保存状态与耗时。后台查询结果与实际展示结果分开记录，才能定位“查了几条”和“显示了几条”的差异。日志本机限量保留，默认不保存密钥、请求头、完整私人日记或照片；需要时由用户主动复制脱敏报告。

现有 `runAgent` 只返回成功工具名称，缺少参数、错误、轮次和结果关联；`replyByAI` 的 JSON 降级也要纳入同一请求日志。通过可选观察回调采集阶段事件即可，无需全局 console 劫持或替换业务 Storage。

流程测试不能复制另一份 agent。聊天页当前同时承担发送、保存、话题和展示控制，可抽出少量共用动作入口供页面与运行器调用。仅调用 `runAgent` 或直接灌入三条记录，只能算模型 / 查询测试，不能标记为完整端侧流程通过。已有 Node 真实模型评测可共用合成样例与断言定义，继续保留默认 CI 的确定性测试。

## 第一组建议场景

三条事实应分三次发送，当前一次最多整理一张草稿：

| 操作 | 验证结果 |
| --- | --- |
| 发送“2025年1月1号领养了点点” | 一张草稿、日期 2025-01-01，确认前未入库；确认后恰好新增一条 |
| 发送“2026年6月1号驱虫了” | 日期 2026-06-01，原文保留；确认后新增一条 |
| 发送“昨天和猫玩了” | 按发送时参考日期解析昨天；确认后新增一条 |
| 当前话题问领养时间、驱虫时间 | 分别只引用对应日记，不显示玩耍等无关引用，不生成新草稿 |
| 新建话题，刷新云端记录，再分别问相同问题 | 从已保存日记得到相同日期，不依赖旧话题上下文；结果与引用仍一致 |

执行前验证草稿日期，错误时不自动保存。断言检查实际日期、记录 ID、保存数量和引用范围，不要求模型措辞逐字一致。新话题查询成功不等同已验证跨设备同步；真实模型输出也不是一次通过就永久可靠。实际流程测试涉及模型及云端请求，不能随打开自检页自动执行。取消、账号 / 家庭变化或小程序中断时停止本轮，不能由迟到回包继续保存。

建议顺序：先修正回复与引用，再加入请求级日志，最后接入这一组端侧流程测试。当前 12 项纯逻辑自检保留，和真实模型 / 云端流程结果分别展示。

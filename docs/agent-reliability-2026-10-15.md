# 自然陈述误查询与两位年份错误诊断

日期：2026-10-15。依据本地 `main` / `c8a70bf` 加当前未提交工作目录、用户反馈截图和当前源码。此轮为诊断与改进建议，未修改 agent、日期解析或业务数据，也没有调用真实模型。

## 两个现象的定位

### 自然陈述返回三条历史记录

截图中“时光册里共 3 条「全部」记录”和三个原记录引用，对应 `utils/query.ts` 中的无事件 / 关键词 / 日期筛选的列表查询。默认 limit 为 3；三条是当前宠物已保存的记录，不是三条与出生事件匹配的记录。

当前 `isHistoryQuery('25年1月1号小猫出生了')` 为 false，不会触发明确历史问题漏调用工具时的代码补救。因此按当前实现，候选路径是模型调用了 `query_records`，或工具模式失败后 JSON 输出包含 `query`。没有当时调用轨迹，不能确定是哪一路，也不能追溯当时的具体模型参数。

执行器会将默认 purpose=answer 的查询摘要直接外显，并优先于模型最终自然回复；context 查询结果也会与最终回复一起展示。只要误选了无筛选列表查询，就会得到截图同类结果。事实陈述应被整理为待确认草稿，用户不必额外再说“帮我记一下”。

### “25年”被记成当前年

`utils/date.ts` 的 `parseDateWords()` 只匹配四位显式年份；“25年”匹配失败后没有终止解析，又命中后面的“1月1号”，按参考日期所在年补成年份。

`utils/draft.ts` 的 `validateDraft()` 忽略模型的 date 字段，从 sourceText 再解析。因此即使模型已给出正确的 2025-01-01，程序仍能将它覆盖成 2026-01-01。这是确定的程序缺陷，不能仅靠增强提示词或增加工具循环解决。

同样需要检查模型摘取 sourceText 时是否把“25年”截掉。只验证子串出现过，不能保证与该事实相连的日期信息完整。

这次是草稿日期值出错，和“当年隐藏年份、跨年显示年份”的展示规则不同。修正为 2025-01-01 后，现有跨年规则会显示 2025 年。截图卡片仍是待确认状态，正式云端保存是之后的用户确认动作。

## 已执行的隔离复现

直接转译并执行当前 TypeScript 函数，固定参考日期为 2026-10-15。使用合成记录和模拟模型工具输出，不读取私人日记、模型密钥或真实云端。

| 检查 | 结果 |
| --- | --- |
| `parseDateWords('25年1月1号小猫出生了', '2026-10-15')` | 2026-01-01，错误 |
| 四位年份对照：2025年1月1号 | 2025-01-01，正确 |
| 模型 date 给 2025-01-01，sourceText 保留两位年份，执行 `validateDraft` | 被覆盖成 2026-01-01 |
| 原句调用 `isHistoryQuery` | false |
| 模拟模型误调用无筛选 `query_records({mode:'list'})` | 返回全部三条的摘要和三个引用，没有草稿，与截图模式一致 |

后两项说明误查询的程序路径能够复现，不等于已经用真实模型复现当时的工具选择。

## 保持简单的修复建议

继续使用单 agent、现有四个工具和六轮预算。优先调整已有工具契约、校验和展示逻辑，不增加新的 agent、路由模型或编排框架。

1. **补齐日期规则并禁止丢失年份。** 支持约定明确的两位年份（本例 25 年 → 2025 年）；世纪有歧义则确认。输入带年份却无法解析时，必须返回待确认，不能退化为当前年月日。检查原文日期与所选证据、规范日期的一致性；证据摘取不能截掉同一事实的日期前缀。
2. **明确事实陈述与查询的工具边界。** 在现有提示词及工具说明中加入出生陈述、出生历史查询、否定、计划和混合请求的对照例。保持结合上下文理解省略追问；不退回用大量关键词正则决定所有语义。模型在现有调用中明确查询用途，不额外增加一次意图分类请求。
3. **区分内部取证与用户答案。** 工具给模型的信息不应自动等同于用户最终看到的信息。记录流程里的背景查询应留在内部上下文；直接历史查询才展示对应的确定性摘要和引用。混合请求可同时返回草稿与相关查询结果。工具模式和 JSON 降级共用校验与展示规则，避免两套口径。
4. **补充小型可观测性与真实模型评测。** 本机开发工具记录有上限的执行摘要：请求标识、工具 / JSON 路径、工具名、筛选参数、日期解析结果、草稿 / 引用数量、修正或失败原因和耗时。默认不保存密钥或完整私人日记。沿用已有 `eval:agent`，增加下面的失败样例及改写版本，不新建评测服务。

工具协议还存在 date 参数声明与执行器忽略该参数的冗余。实现时宜删除无效参数，或清晰定义其辅助作用，并以用户事实证据校验后的日期为准，避免模型和程序各自维护一套日期解释。

优先顺序：日期硬错误 → 记录 / 查询及展示边界 → 轨迹摘要 → 实际模型回归。日期冲突可回灌现有工具循环修正；仍不明确时让用户确认，不需要第二个审查 agent。

## 建议补充的验收样例

| 输入 | 应有结果 |
| --- | --- |
| 25年1月1号小猫出生了 | 一张待确认草稿，日期 2025-01-01，不展示无关历史列表 |
| 帮我记一下25年1月1号小猫出生了 | 同上；不能因为多了指令词才得到正确日期 |
| 2025年1月1号小猫出生了 | 同上，四位年份对照 |
| 小猫是哪年出生的？ | 查询相关已保存依据，没有依据时明确说明 |
| 昨天洗澡了，那上次驱虫是什么时候？ | 昨天的洗澡草稿和相关驱虫查询，各自保持正确用途 |
| 明年1月1号准备办生日会 | 不当作已经发生的生日事实 |
| 世纪不明、日期冲突或无效日期 | 明确追问 / 待确认，不能补成当前年 |
| 先陈述出生事实，再说“把刚才的记下来” | 引用用户原文，保留原年份，不从助手回复取证 |

确定性测试验证日期及展示规则；真实模型评测验证自然说法的任务完成和工具使用。重复运行同一语义的若干改写观察稳定性。验收关注日期、草稿、相关引用和未确认不保存等结果，不把某个唯一工具顺序作为全部标准。

## 维护约定

- 完成重要功能、修复、合并或部署时，同步更新开发记录；无需逐条记录工具调用。
- 每条记录写清日期、问题与结果、关键取舍、验证范围及剩余事项。已知提交号可用于追溯，不猜测发生日期。
- 当前有效的规则写入专题文档；开发记录链接到专题文档，避免重复维护长篇说明。
- 部署记录区分代码提交、上传成功、云函数状态和真实业务验收，不把其中一项当作其他项已完成。
- 历史结论过期时保留其日期背景，并补充新状态。截图标明来源版本与环境。
- 文档随相关代码提交到 Git。不要记录密钥、令牌、用户日记、私人照片或数据库导出。
- 项目内 `.workbuddy/` 已删除，重要历史结论已整理到开发记录；保留忽略规则以防工具再次生成。后续共享信息统一维护在本目录。

开发记录推荐格式：日期与主题 → 变更及原因 → 验证 → 后续事项。日期采用北京时间。

用途：2026 微信小程序开发大赛作品说明；受众为作品评审与体验者。初稿依据北京时间 2026-10-15 的 `main` 基线 `b0d0721` 与当日工作区照片上传调整；2026-10-16 按用户反馈修订照片排布、UX 展示、视觉系列和图示。版本、授权、来源及验证追溯保留在本页，作品正文不展示代码哈希或照片接收信息。本稿不代表平台审核、正式上线或真机业务已全部完成。

## 交付内容

- [说明文档源稿](contest-description.md)：可编辑 Markdown，含三段 Mermaid 源码及图片引用。
- 本机 PDF：`exports/diandian-diary-contest-20261015.pdf`，修订版 11 页，包含正文并排的点点照片、品牌 icon、页面布局展示、三张场景插画、三款宠物头像及三张图示。
- [PDF 构建脚本](build_document.py)：读取 Markdown 排版，使用 Python 的 reportlab、Pillow；字体取自 Windows 的微软雅黑。
- [图示渲染脚本](render_diagrams.cjs)：使用 Mermaid 11.4.1 与 Playwright，导出 SVG 和高分辨率 PNG。
- [图示出版适配脚本](polish_diagrams.cjs)：保留 Antigravity 原交付，生成文稿使用的精简、大字和事实校正版。
- [UX 展示渲染脚本](render_ux.cjs)：读取当前 WCC 模板与 WXSS，使用浏览器适配控件和演示内容，不运行小程序业务。
- [图示源文件](../../../resources/document-assets/diagrams/contest/README.md)：可单独编辑和复用。

PDF 内嵌创作者授权的私人宠物照片，`exports/` 加入 Git 忽略规则，留在本机交付；原始照片仍保存在被忽略的 `resources/document-assets/private/diandian/`。源稿、构建脚本和非私人图示可随仓库保存；按当前项目协作规则创建本地提交，不自动推送。

## 提交前核对

1. 复核赛事平台当前要求的文件格式、大小、报名信息与截止时间。本轮未成功读取官方报名页的完整规则，本文不将转载规则当作已确认要求。
2. 按平台要求准备作品 AppID、小程序码、创作者或团队信息及实际可体验版本；源稿未擅自填写这些信息。
3. 完成独立演示家庭的真实模型、双账号共享、照片访问和真机键盘 / 安全区验收，再按结果更新第 9 节状态表。
4. 如需展示真机 UI，补拍脱敏演示截图并替换第 4 节的浏览器布局展示，来源信息保留在本页。
5. 用户确认文稿及照片选用后，通过赛事平台自行提交或另行授权提交。本轮只生成本地文档，不上传外部平台。

## 本机重新生成

先通过 Codex 的 `load_workspace_dependencies` 获取 Python、Node 与 Node 包目录，使用返回的绝对路径；不要在小程序业务依赖中安装排版包。

原 Mermaid 渲染脚本用于初稿复现。修订版先使用返回的 Node 运行 `polish_diagrams.cjs`，依次传入 Node 包目录和仓库根目录，生成 `publication/` 图示。需要重新生成页面布局展示时，以相同参数运行 `render_ux.cjs`；最后使用返回的 Python 运行 `build_document.py`。

重新导出后用 Poppler 渲染全部页面，检查图示、换行、表格、页码和照片方向。源稿内 Mermaid 代码块与 `publication/` 的 `.mmd` 逻辑稿同步；实际图示布局由 HTML/CSS 源稿控制，不直接手改 PNG。用户授权的 Antigravity 委托只涉及图示需求和指定代码文档，没有向其发送私人猫照片。

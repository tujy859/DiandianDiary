# 开发测试：核心与聊天流程

更新：2026-10-15。入口为「我的 → 开发者工具 → 开发测试」；开启 / 关闭开发者模式见 [测试家庭](new-user-testing.md#入口)。

## 用途与边界

页面统一包含首次使用、核心自检、聊天流程和执行日志；首次使用的欢迎页演练、空白家庭与返回见 [首次使用](new-user-testing.md)。核心自检是在小程序 JavaScript 运行环境中执行的纯逻辑检查，当前保留 12 项，使用固定参考日期 2026-10-15 与内存演示数据，覆盖年份 / 日历、草稿日期与原文、查询事件 / 宠物隔离 / 范围 / 分页、话题边界及照片认领。

旧页面的 32 项包含直接操作当前家庭缓存的本地读写和早期事实分句规则，已移除。核心自检不读写业务 Storage，不临时切换账号 / 家庭，不创建宠物 / 日记，也不请求云端、模型或访问照片文件。核心区域仅读取本机开发开关以控制入口；关闭后不能直接打开或重跑用例。主动使用流程测试或执行日志时，分别按下述边界处理真实业务数据与本机诊断信息。

本地数据读写、登录 / 退出、家庭权限 / 解散和云 SDK 适配等由 `tools/tests/` 自动化回归覆盖。页面自检通过不代表这些接口、真实模型、数据库规则、键盘或真机业务流程已验收；真实环境仍需单独验证。

## 执行日志

同一入口的“执行日志”区域可显式开始 / 停止记录，去聊聊发送消息后返回查看、刷新、复制脱敏报告或清空。默认关闭，关闭开发者模式后停止采集；核心自检仍只使用内存数据，不自动发起真实请求。

`utils/debug-trace.ts` 按当前账号 / 家庭保存最近 12 次请求、每次最多 48 个阶段事件。包括工具名、允许的查询参数、命中记录 ID / 日期、最终外显引用、草稿解析日期、工具 / JSON 路径、降级原因类别、保存状态与耗时。确认保存照片时增加 `photo.start / read / upload / complete / failure`，只采集本轮列表内的照片序号、源文件字节数和上传字节数；失败时 `path` 区分 read / prepare / upload / complete，不保留文件路径、URL、凭证或响应正文。任意关键词会替换为“自定义关键词”，错误不保留服务商原文，不采集密钥、请求头、完整聊天正文或照片。退出登录 / 失去家庭权限时清理对应日志，旧作用域的迟到观察器不能恢复它们；日志存储失败不影响聊天。

## 流程测试

需先登录、配置模型并开启开发者模式。在「聊天流程」点击「准备测试家庭」，通过正式家庭选择接口进入仅当前用户、且当前用户为创建者的测试家庭，创建专用宠物「点点（流程测试）」并开启执行日志。已有合格测试家庭会复用，避免每轮消耗家庭名额；若已达家庭上限且没有可复用测试家庭，准备会报错，不自动删除家庭。

准备后进入真实聊聊页，点击「下一步」逐步执行或「运行全部」依次执行以下八步。打开页面不会自动运行；模型请求使用当前配置，可能计费，测试日记会真实保存到测试家庭云端。

1. 发送「2025年1月1号领养了点点」，检查唯一草稿、日期、原文、无额外回复 / 引用，以及确认前未写库；通过后自动执行正式保存按钮动作，验证保存数量和日期。
2. 同样记录「2026年6月1号驱虫了」。
3. 同样记录「昨天和猫玩了」，按发送当天检查相对日期。
4. 当前话题查询领养时间，只允许目标日记的一个引用及正确日期。
5. 当前话题查询驱虫时间，同样校验。
6. 执行正式新话题动作并强制云端重读，检查旧消息隔离、已保存 ID 与日期仍在。
7. 在新话题查询领养时间。
8. 在新话题查询驱虫时间。

测试失败、停止、离开聊天页、切换账号 / 家庭或关闭开发者模式后，不继续下一步，不自动重试模型请求或恢复旧作用域。失败现场、完成步骤和错误保留在流程测试页；执行日志包含运行 ID 与步骤索引，可复制脱敏报告。中断后可打开现场查看；重新测试先清理本轮。准备阶段响应丢失时，「继续准备」复用同一创建请求 ID，避免重复创建宠物。

「清理本轮测试」需确认，仅按本轮已确认创建的日记 ID 及专用宠物调用正式删除接口，不解散测试家庭，也不清空家庭缓存或全部数据。若宠物下还有手动添加或响应丢失造成的未知记录，则保留宠物与现场并提示处理。停止不能撤销已经发出的云端保存；成功回包且仍在原登录代次的 ID 会纳入清理清单，未知结果不会被猜测删除。删除沿用云端逻辑删除规则，不承诺永久物理清除。通过「返回原家庭」恢复原选择；原家庭已失效时按既有家庭管理处理。

`utils/flow-scenarios.ts` 定义共用样例；`utils/flow-test.ts` 负责步骤和断言，通过聊天页适配器调用真实发送、确认保存、新话题与停止方法，不新增 agent / 服务或替换全局 Storage。默认 CI 的 `tools/tests/flow-test.test.ts` 使用真实聊天页及业务实现、模拟网络 / 云端传输，覆盖工具与 JSON 路径、错误日期 / 引用、停止 / 登出、迟到保存、准备幂等、家庭复用、精确清理与页面关闭。可选 Node 真实模型评测复用日期记录样例，但不替代端侧真实云端验收。

## 核心实现与维护

- [utils/self-check.ts](../utils/self-check.ts) 是唯一的核心用例定义与运行器。每项有稳定 ID、名称与断言，异常只令该项失败，其他项继续。
- [pages/selftest/selftest.ts](../pages/selftest/selftest.ts) 只检查入口权限并展示共用运行结果，没有另一份手写用例。
- [tools/tests/self-check.test.ts](../tools/tests/self-check.test.ts) 用 `test.each(CORE_SELF_CHECKS)` 运行页面同一份用例，默认 `npm --prefix tools test -- --ci --runInBand` 即包含；新增用例自动纳入 CI。
- 查询使用 `queryRecordList(options, records)` 的纯函数核心，正式 `queryRecords` 也调用它。自检传入内存记录，不伪造或替换真实缓存；筛选和排序不改变输入。
- 自动化额外检查禁止 Storage / 文件 / 网络访问、反复运行结果一致、跨年运行不误失败、单项异常继续执行、页面重跑不改登录 / 家庭 / 聊天 / 模型 / 测试状态及关闭后的权限。

修改日期、草稿、查询或上下文时，应检查这些核心用例是否需要更新；只选高价值的快速检查，复杂行为继续放在专题自动化测试，避免将全部回归复制到小程序包里。核心演示日期应显式固定，不能让“10月5日”等固定样例因实际运行月份变化而误报。核心自检不得切换全局 Storage 或真实登录 / 家庭作用域；流程测试仅通过正式选择接口进入已验证的独立测试家庭。

本项验证和预览状态以 [开发记录](development-log.md) 为准。

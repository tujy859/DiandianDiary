# 开发自检

更新：2026-10-15。入口为「我的 → 开发者工具 → 开发自检」；开启 / 关闭开发者模式见 [新手流程测试](new-user-testing.md#入口)。

## 用途与边界

这是在小程序 JavaScript 运行环境中执行的核心逻辑检查。当前保留 12 项，使用固定参考日期 2026-10-15 与内存演示数据，覆盖年份 / 日历、草稿日期与原文、查询事件 / 宠物隔离 / 范围 / 分页、话题边界及照片认领。

旧页面的 32 项包含直接操作当前家庭缓存的本地读写和早期事实分句规则，已移除。新自检不读写业务 Storage，不临时切换账号 / 家庭，不创建宠物 / 日记，也不请求云端、模型或访问照片文件。页面仅读取本机开发开关以控制入口；关闭后不能直接打开或重跑用例。

本地数据读写、登录 / 退出、家庭权限 / 解散和云 SDK 适配等由 `tools/tests/` 自动化回归覆盖。页面自检通过不代表这些接口、真实模型、数据库规则、键盘或真机业务流程已验收；真实环境仍需单独验证。

## 实现与维护

- [utils/self-check.ts](../utils/self-check.ts) 是唯一的核心用例定义与运行器。每项有稳定 ID、名称与断言，异常只令该项失败，其他项继续。
- [pages/selftest/selftest.ts](../pages/selftest/selftest.ts) 只检查入口权限并展示共用运行结果，没有另一份手写用例。
- [tools/tests/self-check.test.ts](../tools/tests/self-check.test.ts) 用 `test.each(CORE_SELF_CHECKS)` 运行页面同一份用例，默认 `npm --prefix tools test -- --ci --runInBand` 即包含；新增用例自动纳入 CI。
- 查询使用 `queryRecordList(options, records)` 的纯函数核心，正式 `queryRecords` 也调用它。自检传入内存记录，不伪造或替换真实缓存；筛选和排序不改变输入。
- 自动化额外检查禁止 Storage / 文件 / 网络访问、反复运行结果一致、跨年运行不误失败、单项异常继续执行、页面重跑不改登录 / 家庭 / 聊天 / 模型 / 测试状态及关闭后的权限。

修改日期、草稿、查询或上下文时，应检查这些核心用例是否需要更新；只选高价值的快速检查，复杂行为继续放在专题自动化测试，避免将全部回归复制到小程序包里。演示日期应显式固定，不能让“10月5日”等固定样例因实际运行月份变化而误报。不得为测试切换全局 Storage 或真实登录 / 家庭作用域。

本项验证和预览状态以 [开发记录](development-log.md) 为准。

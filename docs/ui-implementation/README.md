# UI 实现与验证

本次实际修改了小程序页面及事件代码，设计来源见 [探索记录](../ui-exploration/README.md)。

- 聊聊：品牌小猫欢迎区、四个短标题快捷入口、统一输入区与底部导航；快捷问题填入当前宠物名字，由用户确认后发送。
- 我的：紧凑品牌区、图片头像与资料列表、添加/编辑宠物时选择头像，删除放到编辑表单。
- 时光册：保留竖线/圆点时间轴，单图按宽度展示，多图网格，日期和标签层级调整。
- 插画：相册无记录、画廊无照片、日记已删除三种状态复用现有插画，小尺寸导出后接入页面。
- 数据：稳定 `avatarId` 在本地、云端及本机旧数据导入中保留；缺少 ID 的旧宠物按物种显示默认头像。云端需重新部署 `diaryApi`。
- 包体：原图迁至不入包的 `resources/`，小尺寸 PNG 在 `assets/`，CI 检查源码预算、单图上限和导出一致性，见 [维护说明](../package-size.md)。

## 布局截图的性质

本目录的七张 PNG 使用微信自带 WXML 编译器生成的虚拟节点及实际页面 WXSS，在浏览器里检查 375px / 320px 宽度；不是重新手写的设计稿。输入、按钮、弹层等 TDesign 控件使用浏览器适配，示意数据不写入真实小程序。

它们用于检查布局、图片路径和窄屏溢出，不替代微信模拟器和真机验收。当前开发者工具的服务端口关闭，因此没有通过自动化连接模拟器；WXML/WXSS 本地编译、TypeScript、逻辑测试与体积检查另行执行。

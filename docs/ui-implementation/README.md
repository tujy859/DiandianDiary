# UI 实现与验证

本次实际修改了小程序页面及事件代码，设计来源见 [探索记录](../ui-exploration/README.md)。

2026-10-15 后续补齐了首次使用、空状态行动入口、模型配置和读取失败状态。当前本地修复及布局验证见 [UX 连贯性修复](continuity-2026-10-15/README.md)；下文较早截图与模拟器记录仍描述 UX 分支当时版本。

同日新增开发者专用的新手流程测试入口，演练与测试家庭提示的当前布局检查见 [新手测试工具](new-user-testing-2026-10-15/README.md)。

同日补齐成员退出 / 创建者解散与无家庭状态，当前入口及布局验证见 [家庭管理](family-management-2026-10-15/README.md)。

- 聊聊：品牌小猫欢迎区、四个短标题快捷入口、统一输入区与底部导航；快捷问题填入当前宠物名字，由用户确认后发送。
- 我的：紧凑品牌区、图片头像与资料列表、添加/编辑宠物时选择头像，删除放到编辑表单。
- 时光册：保留竖线/圆点时间轴，单图按宽度展示，多图网格，日期和标签层级调整。
- 插画：相册无记录、画廊无照片、日记已删除三种状态复用现有插画，小尺寸导出后接入页面。
- 数据：稳定 `avatarId` 在本地、云端及本机旧数据导入中保留；缺少 ID 的旧宠物按物种显示默认头像。云端需重新部署 `diaryApi`。
- 包体：原图迁至不入包的 `resources/`，小尺寸 PNG 在 `assets/`，CI 检查源码预算、单图上限和导出一致性，见 [维护说明](../package-size.md)。

## 布局截图的性质

本目录的七张 PNG 使用微信自带 WXML 编译器生成的虚拟节点及实际页面 WXSS，在浏览器里检查 375px / 320px 宽度；不是重新手写的设计稿。输入、按钮、弹层等 TDesign 控件使用浏览器适配，示意数据不写入真实小程序。

它们用于检查布局、图片路径和窄屏溢出，不替代微信模拟器和真机验收。最初服务端口关闭时只完成了上述布局检查；用户随后开启服务端口，现已通过微信官方自动化 SDK 完成实际模拟器验证，详见下节。

## 微信模拟器实测

用户开启开发者工具服务端口后，已通过 CLI 和微信官方 `miniprogram-automator` SDK 连接此 worktree（SDKVersion 3.17.4，模拟器窗口 390 × 753）。以下操作使用临时测试数据执行，结束后恢复了原有本机数据，模型配置未改动：

- 页面编译与启动、四个快捷入口、当前宠物名字填入问题且不自动发送。
- 点击头像选项、点击原生保存按钮、持久化后切换页面仍显示所选头像。
- 宠物切换面板显示图片头像，并能切换到小狗。
- 时间轴两条记录的圆点和连接竖线，单图展示宽度。
- 相册无日记、画廊无照片、日记不存在的三个插画状态。
- 各主页面底部导航可见，边界与实际窗口底部对齐。

测试期间未观察到小程序运行时异常。真实模拟器截图保存在 [simulator/](simulator/)，与本目录先前的浏览器布局截图分开。实测代码包大小及验证摘要见 [simulator/verification.json](simulator/verification.json)。这仍不替代真机键盘、云端部署和双账号验收。

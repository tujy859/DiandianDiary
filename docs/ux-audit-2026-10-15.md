# UX 连贯性核查（2026-10-15）

## 范围与结论

基线：本地 `main`，提交 `c8a70bf`，核查开始时工作目录干净。检查 `app.json` 注册的 8 个页面、底部导航，以及离线提示、待确认卡和草稿编辑器；开发自检页仅检查其入口与页面定位。依据当前 WXML / WXSS / TypeScript、资源清单、UX 整合记录及用户提供的“开始使用”截图。

初次核查结论：新版 UX 已覆盖主要记录与回看页面，但首次使用流程和辅助页面没有完成同一轮整合。问题包含品牌视觉遗漏、下一步入口不连贯、旧说明与现有行为冲突，以及失败状态被显示为空状态。核查阶段仅记录问题；用户随后授权修复，最新实施状态见文末。

对比 `abfa620..dfae78b` 的实际文件变化：UX 合并改动了 `chat`、`album`、`mine`、`diary` 及全局样式，没有改动 `onboard`、`model`、`family`、`offline-bar` 和 `pending-card`。这解释了部分页面虽继承暖白和绿色主题，仍保留之前的视觉与文案。不是图片丢失导致开始使用页显示旧猫头。

## 问题清单

P1 表示说明或状态会误导用户；P2 表示流程与视觉连贯性问题；P3 表示细节一致性。下列描述与行号对应修复前的 `c8a70bf`，保留作问题基线，当前实施状态见文末。

### UX-01 · P2：开始使用页仍是旧品牌占位

- 证据：[onboard.wxml](../pages/onboard/onboard.wxml) 第 18–20 行使用 `t-icon name="cat"`；[onboard.wxss](../pages/onboard/onboard.wxss) 的 `.hero-icon` 是 144rpx 浅绿圆底。该页没有品牌图片引用。
- 对照：聊聊欢迎区、无宠物状态和我的品牌区使用 `assets/brand/app-icon.png`。
- 影响：用户第一眼看到的品牌形象与进入应用后不同。截图下半部较大留白属于该截图的布局观察，不能据此断言所有屏幕都会溢出或留白过多。
- 建议：复用已有品牌小猫，并统一两步引导的图片、标题、说明与按钮间距；第一步按钮可用“连接云端，继续”，避免在尚未完成模型配置时承诺“开始”。长屏和窄屏分别检查构图。

### UX-02 · P2：完成引导后，添加第一只宠物仍需用户自行寻找入口

- 证据：[onboard.ts](../pages/onboard/onboard.ts) 的 `finish()` 固定切到聊聊；无宠物时显示“添加宠物”。[chat.ts](../pages/chat/chat.ts) 的 `goAddPet()`（第 1007–1008 行）仅切到我的；[mine.ts](../pages/mine/mine.ts) 的 `onShow()` 不自动打开表单，实际表单由 `onAddPet()` 打开。
- 影响：点“添加宠物”后只是换页，还要再点一次添加；首次使用的两步条结束后还有一个未预告的必要操作。
- 建议：保持现有云端登录与模型配置前提，在配置完成后明确提示“接下来添加小伙伴”；“添加宠物”动作应抵达实际表单。若用户已有云端宠物，应继续进入聊天，不重复创建。

### UX-03 · P1：离线条承诺不存在的离线保存与自动同步

- 证据：[offline-bar/index.wxml](../components/offline-bar/index.wxml) 第 3 行写“改动会先存本机，联网后自动同步”；但 [chat.ts](../pages/chat/chat.ts) 的 `onSend()` 第 501–504 行离线直接提示“联网后再聊”。[repository.ts](../utils/repository.ts) 的宠物与日记写操作先等待云端成功，再更新缓存，没有与该文案相匹配的日记离线写入队列。
- 影响：用户可能把未成功提交的改动误认为已经被可靠保存，且恢复网络后会自动补交。
- 建议：说明实际能力，例如“当前离线，可查看已缓存的内容；聊天和保存需要联网”。本机当前会话、临时照片和已确认云端日记需区分，不承诺所有改动自动同步。

### UX-04 · P1：模型配置页仍说明会回退到本地演示

- 证据：[model.wxml](../pages/model/model.wxml) 第 4 行写“调用失败时自动回退本地演示规则”；[chat.ts](../pages/chat/chat.ts) 的 `replyByAI()` 实际是工具调用失败后尝试严格 JSON，再失败显示错误和重试，第 657 行明确说明不做无模型兜底。
- 影响：配置页告诉用户失败仍可继续用演示功能，实际却进入错误与重试，体验和预期不一致。
- 建议：改为当前行为说明；首次使用和后续设置共用同一套表述。将“request 合法域名”等开发部署信息放入开发文档或适当帮助，不让普通用户先阅读开发说明才能理解表单。

### UX-05 · P2：同一模型表单在两个入口的提示与保存行为不一致

- 证据：[onboard.ts](../pages/onboard/onboard.ts) 的 `onSaveModel()` 校验必填项并测试连接；[model.ts](../pages/model/model.ts) 的 `onSave()` 直接保存并提示“已保存”，不做相同的完整性校验。两处 `onUseDefault()` 都会在无预设的服务商上提示“没有推荐默认值”，但两个模板始终显示“使用推荐默认值（deepseek-flash）”。
- 影响：切到自定义服务商后，界面仍推荐不适用的默认值；设置页可保存不完整配置，返回主页面又被引导守卫送回配置流程。保存与测试分开可以保留，但各动作应明确。
- 建议：默认值入口按服务商显示；保存时统一完整性校验，并明确区分“配置已保存”和“连接已验证”。设置页突出保存与测试，降低清除配置的视觉权重。

### UX-06 · P2：有插画的空状态也存在行动入口缺口

- 证据：[album.wxml](../pages/album/album.wxml) 无宠物分支（第 18–21 行）只有“先在我的添加”文字；无日记分支有“去聊聊”；无照片分支（第 64–67 行）只有发照片提示，没有按钮。[mine.wxml](../pages/mine/mine.wxml) 无宠物卡片为纯文字，添加入口在分组标题右侧。
- 影响：类似的新手状态，有的可直接操作，有的要求用户理解导航后自行寻找下一步。
- 建议：统一“图 / 标题 / 简短说明 / 主操作”的空状态结构。无宠物提供添加入口，无照片提供去聊聊发照片入口；我的页已有顶部品牌区，可通过卡片内明确按钮改善，不必再堆一张大插画。

### UX-07 · P1：读取失败与内容不存在共用空状态

- 证据：[diary.ts](../pages/diary/diary.ts) 的 `onShow()` 第 37–42 行捕获刷新错误后仍执行 `reload()`；缓存没有该条时，`reload()` 将 `record=null, loading=false`。[diary.wxml](../pages/diary/diary.wxml) 随即进入“这条日记不存在或已被删除”的插画分支。
- 实际核验：用当前 TypeScript 源码转译后执行页面方法，模拟“缓存无该记录 + 云端刷新失败”，最终确实进入上述缺失状态，同时只短暂发出错误 toast。
- 同类风险：时光册先渲染缓存，刷新失败只发 toast；无缓存时会保留“无宠物 / 无日记”分支。此处是源码推导，本次没有模拟器复现。
- 建议：区分加载、成功但为空、读取失败和确认不存在；错误状态提供重试，已有缓存可继续展示并标记刷新失败。不要用缺失插画暗示网络失败等同于删除。

### UX-08 · P3：图标、颜色、字号和操作称呼还有两套口径

- 图标：[pending-card/index.wxml](../components/pending-card/index.wxml) 第 39、43 行仍用系统 emoji“🐾 / 📅”；其他相关操作多用线性图标或新版图片。系统 emoji 的跨设备表现需要统一。
- 文案：待确认卡按钮为“保存这篇”，[chat.ts](../pages/chat/chat.ts) 的 JSON 降级提示却让用户点“保存这条”。建议统一为简短且与按钮完全一致的称呼。
- 样式：全局 `--jd-brand` 为 `#2f6b4f`、文字主色为 `#1f2b25`，新版主页面大量直接使用 `#32694f`、`#253a30` 和 `#78837b`；引导和家庭背景为 `#faf7f0`，其他页面继承 `#faf8f3`。主页面常用 36rpx 侧边距，引导 / 家庭为 28rpx，模型 / 详情为 24rpx。
- 建议：以已认可的主页面视觉为基准整理公共令牌，允许有明确理由的页面差异；不要只为统一数值改变照片和表单的合理布局。全局和待确认卡的阴影在真机上评估后再决定是否减轻。

## 推荐修复顺序

1. 更正文案与失败状态：UX-03、UX-04、UX-07，避免用户误判保存能力和数据是否存在。
2. 连通首次使用：UX-01、UX-02，使用已有品牌图，接通添加第一只宠物的实际操作。
3. 统一表单和空状态下一步：UX-05、UX-06。
4. 收敛图标、操作称呼、样式令牌：UX-08，再检查家庭页和表单的视觉密度。

本次不提出恢复本机模式、跳过现有必要配置或把模型推断当作用户事实，也不需要为了补齐入口立即生成新插画。

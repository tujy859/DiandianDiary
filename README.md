# 记一下喵 · DiandianDiary

[![CI](https://github.com/tujy859/DiandianDiary/actions/workflows/ci.yml/badge.svg)](https://github.com/tujy859/DiandianDiary/actions/workflows/ci.yml)

通过聊天记录宠物生活，在时间轴与照片画廊里回看陪伴时光的微信小程序。

## 当前功能

- **聊聊**：宠物切换、文字与照片输入、待确认记录卡、编辑面板、历史查询与原记录入口。
- **时光册**：时间轴和照片画廊共享记录，照片预览与日记详情。
- **我的**：宠物档案、设置与模型连接配置。
- **记录管理**：用户确认后保存，支持纯文字、纯照片和图文记录的编辑、删除。
- **模型接入**：兼容聊天补全协议的工具调用，以及本地规则演示兜底；每条回复标识来源。

这是本地优先的原型，尚未接入云端数据同步。数据保存在微信本机 Storage，照片保存在小程序用户目录。清理数据或换设备会影响数据可用性。

## 开发运行

1. 使用微信开发者工具导入仓库根目录，项目类型选择小程序。
2. 配置自己有权限的小程序 AppID；仓库的 `project.config.json` 是现有项目配置，AppID 不是服务密钥。
3. 项目使用原生 WXML / WXSS / TypeScript 和 WebView 渲染；TypeScript 由开发者工具编译。
4. TDesign 构建产物已包含在 `miniprogram_npm/`，当前预览不需要重新构建组件库。
5. 编译后可以不配置模型，先用明确标识的本地演示交互体验记录闭环。
6. 如需真实模型，在「我的 → 模型连接配置」填写自己的服务配置；真机请求域名还需按微信要求配置。

`project.private.config.json` 仅用于本机开发，已从 Git 排除。当前开发配置关闭了 URL 检查，不代表真实发布可以跳过合法域名和权限配置。

## 逻辑层测试

需要 Node.js，CI 使用 Node.js 24。

```sh
cd tools
npm ci
npm run typecheck
npm test -- --runInBand
```

目前有 29 个用例，覆盖日期、意图规则、数据存取和模拟模型工具调用。CI 在每次 push、pull request 和手动触发时运行锁定依赖安装、逻辑层类型检查与 Jest 测试。它不包含微信开发者工具编译、真实模型服务调用、照片权限、键盘/布局或真机端到端验证。

## 当前已知限制

- 驱虫、疫苗等共用较宽的「医疗」分类，具体事件查询可能混入其他医疗记录。
- 查询尚无时间范围参数，「这个月」等问法尚不能保证按月份筛选。
- 工具返回的日期和次数由本地代码计算，但最终模型转述尚未强制约束为事实卡字段。
- 所谓 JSON 降级目前只是尝试从普通模型回复中解析 JSON，尚未通过专门提示和结构约束实现可靠 JSON 输出。
- 模型返回的工具参数还需要更严格的日期、范围和语义校验；现有单元测试不能证明真实模型永不误分类。
- 停止生成与生成中切换宠物的请求生命周期仍需补保护。
- 模型 API Key 当前保存在本机配置并由客户端直连使用。正式面向用户分发前需迁往经过身份校验的服务端中转，不应在仓库或客户端包里放置共享密钥。

接下来的重点是补牢查询和请求隔离，再实现宠物、日记、照片的可靠上云与旧数据迁移。

## 视觉与版面设计优化

1. **色彩搭配与风格统一**：
   - **底色**：暖白底（`#FAF8F3`），柔和舒适、不刺眼；
   - **主色**：深绿（`#2F6048` / `#1D382A` / `#EBF3EE`），表达陪伴、安心与专业；
   - **强调色**：少量杏橙（`#D97336` / `#FFF5EB` / `#8F4212`），用于核心决策门禁、高亮状态与重点事实提醒；
   - **字体排版**：采用系统高清中文字体（PingFang SC / 微软雅黑），文字对齐，句式简短规整，消除文字折行单字成行（单字孤行）与碎句。

2. **比例重塑与版面协调（4:3 至 16:9）**：
   - 彻底解决旧图瘦长垂直瀑布问题（旧图比例为 0.73:1 与 0.80:1，在 A4 文档排版中占据过长竖向篇幅且两侧大量留白）；
   - 新图宽高比严格控制在 **1.46:1 至 1.74:1** 之间，结构方正舒展，可直接并入 A4 正文排版。

3. **节点精简与结构控制（6 至 8 个主要节点/分区）**：
   - 结构图：采用顶层架构 + 三等宽主入口栏目，功能收纳于栏内短文本中，避免生成几十个无序散落节点；
   - 确认图：提炼为四步主线流程，辅以决策分支卡片，核心门禁突出；
   - 架构图：精简为四大主要职责分区，上下分层、左右呼应，彻底避免了连线跨区域交叉。

## 事实边界与技术口径核对

本套图示严格遵循 `docs/query-and-tools.md` 与项目实际代码能力，杜绝过度扩写与营销化修饰：

- [x] **模型不能直接保存**：大模型无直接写库工具，仅生成待确认草稿卡片，正式记录必须由用户显式点击确认后写入；
- [x] **查询读取当前宠物已同步缓存**：`query_records` 直接在客户端读取本地已同步日记缓存，非模型直接读库，非服务端实时检索；
- [x] **业务鉴权边界**：云函数 `diaryApi` 是基于微信 OpenID 的纯业务与数据鉴权接口，绝非大模型代理；
- [x] **纯照片通道**：单独发送萌宠照片可直接形成草稿卡片，无需提取文字事实出处，无需虚构文字故事；
- [x] **原始出处永久留存**：正文经模型规范整理，但用户原始输入作为 `rawInput` 永久保留，日记后续编辑不覆盖出处原文；
- [x] **客观严谨边界**：不使用“云端实时同步”、“原文防篡改”、“多模态理解/照片识别”、“工业级可靠”等未验证或超出当前实现的表述；明确指出不承诺无限记忆或消除幻觉。
